# VIDXX

Video monetization platform: curators upload videos, viewers watch a free 10-second preview and unlock the full video with points, and curators earn per paid unlock.

**Stack:** Node.js/Express backend, Supabase (Postgres, Auth, Storage), Paystack payments, vanilla-JS frontend (no build step, works on a 32-bit Windows machine).

## Setup

### 1. Supabase
1. Create a project at supabase.com.
2. SQL Editor: paste and run `supabase/schema.sql` (tables, secure functions, RLS, storage buckets).
3. Authentication → Providers → Email: keep **Confirm email** on (email verification).
4. Authentication → URL Configuration: set Site URL to your `APP_URL`.
5. Storage: the schema creates `videos` (private), `thumbs` and `avatars` (public). Free plan allows 50 MB per file; raise it under Storage settings on paid plans (and change `MAX_MB` in `public/creator.js`).
6. Project Settings → API: copy the URL, anon key and **service_role** key.

### 2. Paystack
1. Dashboard → Settings → API Keys: copy your secret key.
2. Settings → API Keys & Webhooks: set the webhook URL to `https://YOUR-BACKEND/api/paystack/webhook`.
3. Your Paystack account must be able to charge in **KES** (M-Pesa, cards).

### 3. Run
```
cp .env.example .env     # fill in the values
npm install
npm start                # http://localhost:3000
```

### 4. Make yourself admin
Register normally (as a viewer), verify your email, then in the Supabase SQL editor:
```sql
update profiles set account_type = 'admin' where lower(username) = 'yourusername';
```

### Deploy
- **Render:** new Web Service, build `npm install`, start `npm start`, add the `.env` values. It serves the frontend too.
- **Frontend elsewhere (GitHub Pages):** copy `public/` there, set `API` in `public/config.js` to your Render URL, and set `FRONTEND_ORIGIN` on the backend for CORS.

## How the money flows
- Viewer pays KES via Paystack → webhook + server-side verify → `credit_payment()` adds points once (idempotent per reference, amount checked).
- Unlock → `unlock_video()` runs in one DB transaction: row-locks the viewer, deducts points, records the unlock, credits the creator. A unique key on (viewer, video) means no double charge and no duplicate earnings, even on refresh or parallel requests.
- Ledgers are separate: `payments`, `points_ledger`, `earnings_ledger`, `withdrawals`, plus `audit_log`.
- Withdrawals hold funds immediately; admin approves → marks paid after sending the money (M-Pesa/bank), or rejects and the hold is released.

## Video protection
- Full videos sit in a private bucket and are only served via short-lived signed URLs after the server checks unlock status.
- Viewers who haven't unlocked only ever receive a separate 10-second, 480p preview clip generated by ffmpeg when the video is uploaded, so the full file is never exposed before payment.
- Downloading can't be fully prevented in a browser (screen recording, etc.); this blocks the practical shortcuts.

## Settings (Admin → Pricing & settings)
Default unlock price (points), creator rate per paid unlock (USD), minimum withdrawal, preview length, USD→KES rate, and the points packages. Individual video prices can be overridden in Admin → Videos.

## Before going live
- Have a lawyer review the Terms, Privacy, Payout and Content pages (`LEGAL` in `public/app.js`). They are plain-language starting points.
- The 18+ gate is a sign-up confirmation checkbox. Stronger age/identity verification needs a third-party service.
- Check Paystack's acceptable-use rules cover your content category.
- ffmpeg comes from the `ffmpeg-static` package. If your host can't run it, previews won't generate and videos can't be approved (set `ALLOW_UNSECURED_PREVIEW=true` only for local testing).

## Live streaming, comments and messages
- **Sections:** Explore has two tabs, Videos and Live. Videos and live chats both have comment sections.
- **Live:** curators go live from the browser (Go Live page). Viewers pay 30 points per minute (admin setting). Creators earn a per-viewer-minute amount (admin setting, default $0.001).
- **Messages:** curators message any viewer for free. A viewer's first 2 replies in each conversation are free, then 3 points each (both admin settings). Viewers can block a creator.
- **LiveKit setup (needed for Live):** create a free project at livekit.io, then add these environment variables on Render: `LIVEKIT_URL` (starts with `wss://`), `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`. Re-run `supabase/schema.sql` in Supabase (safe to re-run).

## Currency for visitors outside Kenya
Visitors outside Kenya are auto-detected (Cloudflare country header, with an IP lookup fallback) and see prices in USD at the `usd_to_kes` rate (admin setting, default 129). They can switch KES/USD on the Buy Points page. Paystack is always charged in **KES**, so no USD account is needed; their card is converted by their bank. Unknown location defaults to KES. Run `supabase/migration_usd.sql` once (it is also included in `schema.sql`).
